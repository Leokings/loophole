## Blockers

### 1. Stances are sent in the wrong shape, so every reveal fails
`normalizeStances` sends `JSON.stringify({"2": "SUPPORT"})`, and `{}` when there are none. `reveal_action` → `_strict_stances_json` requires a **list**: `[{"law_id": 2, "stance": "SUPPORT"}]`, or `[]`. Anything else raises `_expected("STANCES")`, so the first reveal of round 1 would stop the run.
- Make `stance()` and `commonAction()` build the list form.
- `normalizeStances` should accept only arrays.

### 2. UNDERMINE actions carry `target_law_id`, so the contract rejects them
Rounds 5, 6 and 9 put the cited law in `target_law_id` so `assertTargetClass` can find the law's sponsor. For `UNDERMINE`, the contract requires `target_law_id == 0`; otherwise `ACTION_UNUSED_FIELDS`.
- Use a separate scenario-only field (for example `class_law_id`) for the class assertion.
- `actionArgs` must send `target_law_id` only for action types that use it (`AMEND_LAW` / `REPEAL_LAW` / `VETO_LAW` / `FILE_SUIT`).

### 3. `round3` references an undefined `ids`
`stance("REVOLUTIONARIES", ids.rule, …)` throws a `ReferenceError`. Add `const ids = lawIds(ctx);`.

### 4. Scheduling would burn commit windows
`play()` sequences commits one at a time, waits for **finality** on `advance_round`, and the scenario runs certification, crisis and case stages (with finality and up to 45-minute effect waits) **after** advancing. Those stages run inside the next round's 300 s commit window, so that round's commits would miss the deadline.

Apply **"Revision 2"** at the top of `docs/v7/PHASE_5_DEMO_SCENARIO.md`:
- **R2-1:** 600 s commit/reveal; batched submit-then-await; `advance_round` sequenced on ACCEPTED.
- **R2-2:** every non-round stage runs while parked at `READY_TO_ADVANCE`, before that round's advance, following the stage table.
- **R2-3:** the crisis response moves to r5.

Measured on StudioNet today: an AI `advance_round` took 59–145 s to reach ACCEPTED.

### 5. Missing stages and assertions
- The `guards` stage is missing entirely:
  - `file_case_from_republic` from an EOA → `REPUBLIC_ONLY`
  - `record_holding` from an EOA → `COURT_ONLY`
  - the `recover_case_effects(A)` replay → success with both flags false, plus unchanged read-backs
- The r8 `crisis_skipped: true` assertion.
- The r10 fallback check passes vacuously when `actions` is empty. Require exactly 4 actions, all `AI_FALLBACK`.
- Briefs are submitted as finalized steps before resolving, and can miss the 600 s brief window. Submit them right after each filing (sequenced on ACCEPTED), or drop them; briefs are optional.
- A shared read rate limiter (≤ 20 reads/min) in `ctx.read`.

### 6. Add a contract-shape test so this class of bug can't recur
Mocks that accept anything hid items 1–3. Add a test with **no network** that does both of the following:
- Runs every `play()` action list through a **Python-side check**. The simplest route: a small pytest in `tests/direct/` that loads the scenario's action lists from a JSON export (`node web/scripts/v7-demo-scenario.mjs --export-actions > tests/direct/fixtures/v7_demo_actions.json`, regenerated by the test), then deploys the republic in direct mode and asserts that `_canonical_action_values(...)` and `_strict_stances_json(...)` accept every scripted action. Use the matching snapshot state where needed, or at least the field-shape rules: unused fields empty, stances as a list, office title, target law only where allowed.
- Asserts in vitest that the scenario's stage order matches the Revision 2 table.
